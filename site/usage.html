Quick start

A merge, rebase or cherry-pick stopped with conflicts. This is how you get through it with AfterGit. The full user guide describes every command and preference.

1 Open a conflicting file

Double-click the file in Git Staging (or press Enter, or choose its Merge Tool entry). With “Use AfterGit as the Merge Tool” (Preferences → AfterGit, on by default) a text conflict opens in AfterGit instead of EGit’s merge editor.

You can also right-click a conflicted file and choose Resolve in AfterGit… in Package Explorer, Project Explorer or the Team menu (right below EGit’s Merge Tool), or use the view menu or the toolbar of Git Staging.

Binary and modify/delete conflicts offer Keep Ours, Keep Theirs or Delete File. Submodules, symbolic links and renames go to EGit’s Merge Tool.

2 Resolve the conflicts

When the file opens, AfterGit resolves what it can on its own: non-conflicting changes, word-level merges and, where the file has a structure, Java imports and members, .properties keys and MANIFEST.MF headers. These blocks are teal with an “A” and stay hatched until you mark them reviewed (✓). Revert and Re-run take them back.

Open conflicts are red. In the connectors, » and « take a side (Ctrl+click replaces instead of appending) and × ignores it. The toolbar adds Take Both, and “⋯” holds Revert Block and Compare with Base.

You can also type in the result. It is a real editor, and for Java files with JDT a Java editor with live errors, quick fix and content assist.

Move between conflicts with ◀ Conflict ▶ and ◀ Unresolved ▶ in the toolbar. Undo and redo include the state of every block. The block colours are explained on the overview.

3 Save & Mark Resolved

Save & Mark Resolved, at the right edge of the toolbar, saves the file, stages it (git add) and closes the resolver once every conflict is resolved; the status line names any auto-resolved blocks you have not reviewed. With conflicts left it asks: Cancel, Save without staging, or Save with markers (writes the open conflicts as markers in the repository’s merge.conflictStyle). Ctrl+S only saves.

The file moves to Staged Changes in Git Staging at once. When every file is staged, commit or continue the rebase as usual.

Many files at once

Select files, folders or projects (or entries in Git Staging) and choose Resolve All Simple Conflicts, or use Team (or the Git Staging view menu) → Resolve All Simple Conflicts in Repository. It runs in the background, resolves every conflict that can be resolved automatically, writes the rest as conflict markers, and ends with a summary of the files fully resolved, partly resolved and left untouched. From the summary:

  • Stage Resolved Files runs git add on the fully resolved files only.
  • Open Remaining in Editor opens the resolver for every other conflicted file.
  • Undo Resolve All puts back every written file byte for byte, until the summary closes.

Key bindings

These work in the context “Resolving Merge Conflicts”. Change them under Preferences → General → Keys, where every resolver command of the category “AfterGit” can get a key. On macOS Ctrl is Cmd.

Default key bindings of the resolver
KeysAction
Ctrl+. / Ctrl+,Next / previous change
Ctrl+Alt+. / Ctrl+Alt+,Next / previous conflict (any state)
Ctrl+Shift+. / Ctrl+Shift+,Next / previous unresolved conflict
Ctrl+Alt+← / Ctrl+Alt+→Take left / take right
Ctrl+Alt+BTake both (left first)
Ctrl+Alt+IIgnore
Ctrl+Alt+1 … Ctrl+Alt+4Layouts: Ours | Result | Theirs, Left + Result, Result + Right, Result Below
Ctrl+Alt+SShow / hide the Structure column
Ctrl+Z / Ctrl+Shift+ZUndo / redo, block states included

Settings

  • Colours and the colour schemes (Default, Colour-blind safe, High contrast) are under Preferences → AfterGit → Appearance, with light and dark values of their own.
  • Project → Properties → AfterGit stores the settings that shape results in .settings/net.aftergit.merge.ui.prefs, so a team can share them.
  • Resolve with AI and AI Agents (MCP) are set up under Preferences → AfterGit once their features are installed; see the user guide.
